A complete machine learning pipeline for predicting hourly bike rental demand, with an interactive Streamlit app for exploring predictions.

## Dataset

This project uses the **Bike Sharing Demand** dataset from Kaggle, containing two years of hourly rental logs from the Capital Bikeshare program in Washington, D.C., combined with weather and seasonal data.

1. Download `train.csv` from the [Kaggle competition page](https://www.kaggle.com/c/bike-sharing-demand/data).
2. Rename it to `bike_rental.csv`.
3. Place it in `data/raw/bike_rental.csv`.

### Feature Reference

| Feature | Type | Description |
|---|---|---|
| `datetime` | String | Hourly timestamp, e.g. `2011-01-01 00:00:00` |
| `season` | Integer | 1 = Spring, 2 = Summer, 3 = Fall, 4 = Winter |
| `holiday` | Integer | 1 if the day is a holiday, 0 otherwise |
| `workingday` | Integer | 1 if neither a weekend nor a holiday, 0 otherwise |
| `weather` | Integer | 1 = Clear, 2 = Mist/Cloudy, 3 = Light Snow/Rain, 4 = Heavy Rain/Snow |
| `temp` | Float | Temperature (°C) |
| `atemp` | Float | "Feels like" temperature (°C) |
| `humidity` | Float | Relative humidity (%) |
| `windspeed` | Float | Wind speed |
| `casual` | Integer | Non-registered rentals (dropped before training) |
| `registered` | Integer | Registered-user rentals (dropped before training) |
| `count` | Integer | Target — total rentals in that hour |

## Key Techniques

* **Temporal feature extraction** — `hour`, `dayofweek`, `month`, and `year` are parsed out of the raw timestamp.
* **Data guardrails** — continuous weather readings are clipped at a lower bound of 0.
* **Derived features** — `is_weekend` and `is_rush_hour` flags built from the temporal features.
* **Leakage prevention** — `casual` and `registered` are dropped before the split, since they sum directly to the target.
* **Categorical encoding** — `season` and `weather` are one-hot encoded rather than treated as ordinal integers.
* **Feature scaling** — continuous variables are standardized with `StandardScaler` inside a `ColumnTransformer`, fit only on training folds.
* **Pipelines** — all preprocessing and modeling steps are encapsulated in `Pipeline` objects to prevent leakage during cross-validation.
* **Hyperparameter tuning** — `RandomizedSearchCV` tunes the Random Forest and Gradient Boosting models.

## Models

* **Linear Regression** — a fast, interpretable baseline.
* **Random Forest Regressor** — tuned via `RandomizedSearchCV`.
* **Gradient Boosting Regressor** — tuned via `RandomizedSearchCV`.

All three are benchmarked against a 20% holdout test set using **MAE**, **RMSE**, and **R²**. `model_comparison.py` runs all three, writes the results to `reports/metrics_report.txt`, and saves the best-performing pipeline to `models/random_forest_model.pkl`.

## Setup

1. Clone the repository and create a virtual environment:
   ```bash
   python -m venv .venv

   # macOS/Linux
   source .venv/bin/activate

   # Windows
   .venv\Scripts\activate
   ```

2. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```

3. Add the dataset (see [Dataset](#dataset) above).

## Usage

Train and compare all three models, and save the best one:
```bash
python -m src.model_comparison
```

Run a single model on its own:
```bash
python -m src.train_model
python -m src.train_random_forest
python -m src.train_gradient_boosting
```

Generate the EDA charts:
```bash
python notebooks/eda.py
```

Score a single example from the command line:
```bash
python -m src.predict
```

Run the tests:
```bash
pytest src/tests/
```

## Streamlit App

Once a model has been trained and saved (`python -m src.model_comparison`), launch the interactive app:

```bash
streamlit run app/app.py
```

The app lets you set the date, time, season, weather, and holiday/working-day flags in the sidebar and returns a predicted rental count for that hour.
